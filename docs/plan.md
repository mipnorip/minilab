# ЭЖЛ — «Электронные журналы лаборатории»
## Функциональный план MVP

**Версия:** 1.3 · Ж-04/03 (прекурсоры) перенесён в MVP · стек: React + Python/FastAPI + PostgreSQL
**Уровень:** MVP / демонстрационный прототип (проба пера)

---

## 1. Контекст и цель

Вузовская лаборатория (ЦКП «КУЭП») ведёт журналы СМК на бумаге: каждый журнал имеет шифр, ответственного, периодичность проверки и срок хранения. Проект переводит журналы в web-систему с сохранением дисциплины ГОСТ ISO/IEC 17025-2019.

**Цель MVP:** работающий прототип, который ведёт несколько журналов «по правилам» и расширяется до полного перечня настройкой шаблонов, без программирования новых экранов.

**Референсы:** ЛИМС НИОКР Zyfra Quality Lab (СИБУР ПолиЛаб), ИНТЦ «Сириус» (среда развития проекта), ГОСТ ISO/IEC 17025-2019 (п. 8.3 «Управление документами», п. 8.4 «Управление записями», 7.10, 7.11).

**Решения по рамкам:**
- Учёт реактивов и материалов — собственный модуль системы, интеграция с внешней системой реактивов не делается.
- Аутентификация — логин/пароль, роли и аудит; квалифицированная ЭП (ФЗ-63) не входит.
- Архитектура — web-клиент + микросервисы; ядро системы собрано из **переиспользуемых модулей** (раздел 7), не зависящих от лабораторной специфики.
- Стек зафиксирован: React (SPA) + Python/FastAPI (все backend-сервисы) + PostgreSQL; поставка через Docker (раздел 7.4).
- Принцип «отдать и не поддерживать»: конструктор форм, хранилище записей, аудит и доступ — самостоятельные модули; лабораторная логика живёт в пресетах шаблонов и настройках, а не в коде модулей.

## 2. Пользователи и роли

| Роль | Основные действия |
|---|---|
| Лаборант / инженер | вносит записи в назначенные журналы; списывает материалы; исправляет свои записи с указанием причины |
| Ответственный за журнал | ведёт журнал; закрывает строки; помечает журнал готовым к проверке |
| Менеджер по качеству | видит все журналы; проверяет по графику; ведёт несоответствия |
| Заведующий лабораторией | просмотр всех журналов; отчёты; экспорт в PDF |
| Администратор | пользователи и роли; справочники; шаблоны и конструктор форм; реестр журналов |

Права задаются матрицей «роль × журнал × действие» (просмотр / ввод / исправление / проверка / администрирование).

### 3.3 Не включаем — и почему

| Позиция | Причина |
|---|---|
| Ж-04/10 · 9.17 — Журнал передачи дел в архив и выдачи дел из архива / «Документы архивного хранения» | **Мета-журнал об управлении журналами.** В электронно системе архив — это статус журнала («ведётся / закрыт / в архиве»), а передача и выдача — системные операции, которые уже фиксируются журналом аудита. Отдельная форма дублировала бы системную функциональность. |
| Ж-04/08 — Журнал инструктажа по технике безопасности | **Кадровый контур охраны труда, вне лабораторного документооборота.** Инструктаж подтверждается личными подписями инструктируемых; без квалифицированной ЭП электронная версия слабее бумаги и не даёт выгоды (записи редкие). Остаётся бумажным. |
| 9.16 — Журнал регистрации изменений документации | **Это управление документами СМК (НД, методики, ГОСТы), а не лабораторные записи.** Другой контур: версии документов, актуальность, ознакомление — предмет отдельного проекта документооборота. Если понадобится — можно завести простой формой в Phase 3. |

**Ж-04/03 (прекурсоры) — включён в MVP по решению лаборатории.** Учёт ведёт модуль «Материалы» в усиленном режиме: обязательная привязка к партии, инвентаризация, отдельные права на списание, расширенный аудит событий. Если по конкретному веществу нормативно требуется бумажный журнал — для него ведётся бумажная копия с отметкой в системе.

Примечание: в исходных перечнях нет журнала поверки/калибровки средств измерений (в вузовской лаборатории поверка обычно централизована метрологической службой вуза), поэтому он исключён из MVP; механику напоминаний по срокам в MVP закрывает журнал 9.5, а обслуживание оборудования — 9.13 в Phase 2.

## 4. Функциональные блоки

Приоритеты: **M** = обязательно для MVP, **S** = желательно в MVP, **P2** = после MVP.

### 4.1 Пользователи и доступ — M
- Вход по логину и паролю; сессия с таймаутом.
- Назначение ролей; закрепление ответственных за журналами.
- Матрица прав «роль × журнал × действие».

### 4.2 Справочники (мастер-данные) — M
- Сотрудники.
- Реестр журналов: шифр (Ж-04/XX), название, ответственный, периодичность проверки, срок хранения, статус (ведётся / закрыт / в архиве).
- Материалы (реактивы, стандартные образцы): наименование, партия, единица измерения, срок годности, место хранения, тип.
- Методики: номер, название, срок актуальности.
- Оборудование и холодильники (для 9.4, 9.5, 9.12, 9.13 — P2, минимум для 9.5 в MVP).
- Помещения (P2).

### 4.3 Конструктор форм журналов — M (ядро системы)
- Шаблон журнала = набор колонок. Типы колонок: текст; число (с единицей измерения); дата; да/нет; список значений; ссылка на справочник; автополе (номер строки, дата, автор).
- Расчётная колонка: формула по другим колонкам.
- Признак обязательности; значение по умолчанию.
- Шаблон можно создать «с нуля» или из готового пресета (16 журналов из раздела 3).
- Версионирование форм: изменение шаблона не ломает ранее внесённые записи.

### 4.4 Ведение журналов — M
- Список «мои журналы» / «все журналы» (по правам).
- Таблица записей: сортировка, фильтр по дате, автору, статусу.
- Создание записи; автонумерация строк; автополя заполняются системой.
- Статусы записи: черновик → внесена → проверена.
- Удаление записей запрещено (только закрытие/исправление).
- Связи между журналами: строка результата ссылается на образец, методику, списанные материалы (прослеживаемость по 17025).

### 4.5 Исправления и аудит — M (ключевой блок соответствия ГОСТ)
- Изменение внесённой записи = «исправление»: фиксируются прежнее значение, новое значение, автор, дата и **причина** (ошибка вычисления / опечатка / иное — с комментарием).
- Прежнее значение никогда не стирается — хранится вся история строки.
- Карточка записи: лента «кто — когда — что — почему».
- Системный журнал аудита: входы, смена ролей, назначение ответственных, закрытие журналов, операции с архивом.

### 4.6 Проверки журналов — S
- График проверок из реестра журналов (периодичность в неделях — из перечня СМК).
- Отметка «журнал проверен (кем, когда)» фиксируется как событие журнала.
- Панель менеджера по качеству: что просрочено, что ожидает проверки, открытые несоответствия.

### 4.7 Напоминания — S
- Панель уведомлений: срок годности материала; плановая запись не внесена (например, температура холодильника за день); приближение плановой проверки журнала; срок хранения журнала истекает (передача в архив).
- Настройка: за сколько дней предупреждать.
- E-mail-рассылка уведомлений — P2.

### 4.8 Поиск, отчёты, экспорт — S
- Поиск и фильтры по журналам, датам, авторам, статусам.
- Экспорт журнала в PDF в виде бумажной формы (с историей исправлений в приложении) — для инспекции при аккредитации.
- Сводный отчёт за период: количество записей, исправлений, просроченных проверок.
- «Карта соответствия 17025»: каждый журнал привязан к пунктам стандарта (P2, сильный аргумент на защите).

### 4.9 Модуль «Материалы» (реактивы, СО, прекурсоры; свой, без внешней интеграции) — M
- Поступление: кто принял, сколько, партия, срок годности.
- Списание: кто, сколько, на какую запись какого журнала (связь с результатом испытания).
- Остатки на местах хранения.
- Усиленный режим для прекурсоров (Ж-04/03, входит в MVP): обязательная привязка к партии, отдельное право на списание, инвентаризация, расширенный аудит.
- Истечение срока годности → уведомление; материал с истёкшим сроком помечается и блокируется для списания; операция «проверка пригодности» (9.10) может вернуть его в оборот с фиксацией.
- Операции автоматически формируют записи журналов учёта (Ж-04/04, 9.7, 9.10, Ж-04/03).

### 4.10 Хранение и архив — S
- Атрибуты «срок хранения» и «дата закрытия» у журнала.
- Статус «в архиве»: журнал доступен только для чтения и экспорта. Закрытие и выдача из архива — системные операции с записью в аудит (замещает Ж-04/10).
- Резервное копирование: ручная/регулярная выгрузка данных и отметка о копировании (закрывает п. 8.4 ГОСТ).

## 5. Перенос бумажных правил ГОСТ в функциональность

| Требование (ГОСТ 17025 / практика СМК) | Реализация в системе |
|---|---|
| Исправление: зачеркнуть, указать верное, дату, подпись, причину | Исправление поля с причиной; прежнее значение сохраняется в истории |
| Записи нельзя удалить или незаметно изменить | Запрет удаления; append-only история; аудит всех действий |
| Периодическая проверка журналов с фиксацией | График проверок (4/5/6 недель по перечню СМК); отметка «проверено (кем, когда)» |
| Разграничение доступа | Роли и матрица прав по журналам |
| Защита от потери записей | Резервное копирование; отметки о копиях |
| Сроки хранения и архив | Атрибуты журнала; статус «в архиве»; архивная выдача через аудит |
| Идентификация журналов (шифр, форма, ответственный) | Реестр журналов (шифры Ж-04/XX) и шаблоны форм |
| Прослеживаемость: образец → методика → первичные данные → результат → материалы | Связи между записями журналов и справочниками |

## 6. Демо-сценарий (5–7 минут)

1. **Администратор:** создаёт журнал «Регистрация и движения образцов» (Ж-04/01) из пресета, назначает ответственного.
2. **Лаборант:** регистрирует образец; вносит результат испытания (Ж-04/02) — расчёт выполняется автоматически; списывает реактив (Ж-04/04) — остаток уменьшается.
3. **Прекурсоры (Ж-04/03):** лаборант пытается списать подконтрольное вещество — нет отдельного права; инженер с правом списывает с привязкой к партии — событие уходит в журнал и расширенный аудит.
4. **Лаборант:** допускает ошибку → исправляет с причиной → показывает историю записи «кто — когда — почему».
5. **Система:** панель уведомлений: реактив скоро истекает; температура холодильника (9.5) за сегодня не внесена; журнал ждёт плановой проверки.
6. **Лаборант:** вносит температуру холодильника — ежедневная запись с автодатой.
7. **Менеджер по качеству:** открывает панель проверок, проверяет журнал, ставит отметку.
8. **Заведующий:** выгружает журнал в PDF в бумажной форме.

## 7. Модульная декомпозиция: переиспользуемое ядро + лабораторный слой

### 7.1 Переиспользуемые модули (не знают про лаборатории)

| Модуль | Ответственность | Кто использует |
|---|---|---|
| **Конструктор форм** | шаблоны: колонки, типы, формулы, версии форм | все журналы; самостоятельный продукт — можно отдать и не поддерживать |
| **Хранилище записей** | записи по шаблону: статусы, нумерация, поиск, фильтры | все журналы |
| **Аудит** | append-only события «кто — когда — что — почему» для любых сущностей | все модули |
| **Доступ** | пользователи, сессии, роли, матрица прав | все модули |
| **Материалы** | номенклатура, партии, поступление/списание, остатки, сроки | Ж-04/04, 9.7, 9.10, Ж-04/03 |
| **Планировщик** | напоминания по расписанию и по срокам любых сущностей | 9.5, проверки журналов, сроки годности |
| **Экспорт** | PDF бумажной формы из шаблона | все журналы |
| **Связи** | связи записей между журналами | прослеживаемость (образец ↔ результат ↔ материалы) |

### 7.2 Лабораторный слой (тонкая настройка, не код)

Пресеты 16 журналов из раздела 3; справочники методик, оборудования, помещений; семантика ролей; правила периодичности проверок.

### 7.3 Принцип «отдать и не поддерживать»

Зависимость односторонняя: лабораторный слой использует модули, модули про лабораторию не знают. Контракт между слоями — схема шаблона и события аудита. Следствие:

- конструктор форм + хранилище записей можно вынести в отдельный продукт и передать другой команде/лаборатории;
- добавление журнала из перечня — создание пресета, код не меняется;
- смена правил (периодичность, сроки хранения) — настройки реестра, не релиз.

### 7.4 Сервисы, стек и поставка

**Стек:** React (SPA) + Python/FastAPI (все backend-сервисы, один язык) + PostgreSQL (один инстанс, отдельная схема на сервис — любую схему можно вынести в отдельную БД без изменения кода).

Почему Python, а не Go/Rust: узкое место MVP — скорость разработки и читаемость, а не производительность; один язык для всех сервисов упрощает поддержку и передачу проекта.

**Сервисы (MVP):** gateway (единая точка входа: маршрутизация, JWT, отдача статики), web (React), auth-svc, forms-svc, records-svc, materials-svc, scheduler-svc, audit-svc. reports-svc (PDF, сводные) — Phase 2.

**Поставка:**
- Dockerfile для каждого сервиса; docker-compose поднимает стек целиком: PostgreSQL, миграции при старте, все сервисы, gateway, web.
- Сид-данные: пресеты 16 журналов, демо-пользователи всех ролей, тестовые записи.
- README на русском: назначение, архитектура, переменные окружения, инструкция запуска (docker compose up) и сценарий проверки после запуска.

## 8. Вехи

1. Модель данных, справочники, пользователи и роли.
2. Конструктор форм + хранилище записей + журнал Ж-04/01 «Регистрация и движения образцов».
3. Исправления и аудит: причина, история, запрет удаления.
4. Ж-04/02 «Результаты испытаний» (формулы, связи) + модуль «Материалы» (поступление, списание, остатки, сроки) с усиленным режимом прекурсоров (Ж-04/03).
5. Журнал 9.5 «Температура холодильников» (ежедневные записи, планировщик напоминаний).
6. Экспорт PDF и сводные отчёты.
7. Пресеты 12 журналов Phase 2 (настройка, без кода) + сквозной демо-сценарий.

## 9. Границы MVP (не входит)

- Квалифицированная электронная подпись (ФЗ-63).
- Интеграция с существующей внешней системой реактивов.
- Журналы, исключённые в разделе 3.3 (архивный мета-журнал, инструктаж ТБ, изменения документации).
- Подключение лабораторных приборов и датчиков (автоматический сбор данных).
- Мобильное приложение; работа офлайн; несколько лабораторий в одной инсталляции.
- Валидация методик, карты Шухарта и статистика ВЛК (только форма журнала).

---

## 10. Критерии готовности MVP

- Журнал создаётся из пресета и конструктором; форма настраивается без программирования.
- Лаборант вносит запись; исправление требует причину и сохраняет историю; удалить запись нельзя.
- Роли разграничены: лаборант не проверяет журналы и не видит административных разделов.
- Списание реактива уменьшает остаток и оставляет след в журнале учёта; истекающий срок даёт уведомление.
- Списание прекурсора требует отдельного права и привязки к партии; событие фиксируется в журнале Ж-04/03 и аудите.
- Пропущенная ежедневная запись температуры холодильника даёт уведомление.
- Менеджер ставит отметку о проверке; заведующий выгружает журнал в PDF.
- Аудит показывает полную картину «кто — когда — что — почему» для любой записи.
- Добавление любого журнала из Phase 2 — создание пресета формы, без разработки.
