# ЭЖЛ — Электронные журналы лаборатории

MVP системы электронного документооборота для вузовской лаборатории (ЦКП «КУЭП»):
заменяет бумажные журналы системы менеджмента качества и ведёт их **по правилам
ГОСТ ISO/IEC 17025-2019** — с аудитом, исправлениями «с причиной», плановыми
проверками и прослеживаемостью.

## Что умеет MVP

| Возможность | Как реализовано |
|---|---|
| 5 журналов из реального перечня лаборатории | Ж-04/01 (образцы), Ж-04/02 (результаты испытаний), Ж-04/04 (реактивы), Ж-04/03 (прекурсоры, усиленный режим), 9.5 (температура холодильников) |
| Конструктор форм журналов | шаблоны с колонками (текст, число с единицей, дата, список, ссылки, автополя), расчётные колонки по формуле, версии форм |
| Записи «по правилам» | удалить нельзя; исправление требует причину (В/О/И) и сохраняет прежнее значение в истории; отметка «журнал проверен» фиксируется |
| Модуль «Материалы» | реактивы, стандартные образцы, прекурсоры: партии, поступление, списание, остатки, сроки годности, инвентаризация |
| Усиленный режим прекурсоров | списание только с отдельным правом, привязка к партии, инвентаризация, расширенный аудит |
| Напоминания | истекающий срок годности, невнесённая ежедневная запись (9.5), просроченная проверка журнала |
| Роли | лаборант/инженер, ответственный за журнал, менеджер по качеству, заведующий, администратор |
| Экспорт | CSV, печать бумажной формы (PDF средствами браузера) |
| Журнал аудита | append-only «кто — когда — что — почему» для всех действий |

## Архитектура

Web + микросервисы (React · Python/FastAPI · PostgreSQL):

```
Браузер (React SPA)
      │
   Gateway (nginx) ─── единая точка входа: /api/* и статика SPA
      │
      ├── auth-svc       пользователи, роли, JWT                :8001
      ├── forms-svc      конструктор форм, версии шаблонов       :8002
      ├── records-svc    реестр журналов, записи, исправления    :8003
      ├── materials-svc  реактивы, СО, прекурсоры                :8004
      ├── scheduler-svc  напоминания и уведомления               :8005
      └── audit-svc      append-only журнал аудита               :8006
                       │
                  PostgreSQL (отдельная схема на сервис)
```

- Все сервисы пишут события в **audit-svc** — соответствие 17025 собрано в одном месте.
- Межсервисные вызовы — REST; аутентификация — JWT (выдаёт auth-svc) или внутренний
  ключ `X-Internal-Key` для системных вызовов.
- PostgreSQL один инстанс, у каждого сервиса своя схема (`auth`, `forms`, `records`,
  `materials`, `scheduler`, `audit`) — схему можно вынести в отдельную БД без
  изменения кода.

## Запуск

Нужен только Docker (с docker compose).

```bash
cp .env.example .env        # секреты; для демо подойдут значения по умолчанию
docker compose up --build -d
```

Через ~1–2 минуты (миграции + демо-данные) открыть: **http://localhost:8080**

Проверка после запуска (весь демо-сценарий через API, 24 проверки):

```bash
bash scripts/smoke.sh
```

Другие команды:

```bash
docker compose logs -f          # смотреть логи
docker compose up --build -d    # пересобрать после изменений кода
docker compose down             # остановить (данные останутся)
docker compose down -v          # остановить и удалить данные (свежий старт)
```

Порт наружу меняется в `.env` (`APP_PORT=8080`).

## Демо-пользователи

Пароль у всех: `demo123`

| Логин | Роль | Особенности |
|---|---|---|
| `admin` | администратор | всё: шаблоны, журналы, пользователи |
| `head` | заведующий лабораторией | просмотр всех журналов, аудит, экспорт |
| `qm` | менеджер по качеству | проверки журналов, несоответствия, аудит |
| `eng1` | инженер | **право на списание прекурсоров**, ответственный за журналы |
| `lab1` | лаборант | вносит записи, списывает реактивы |
| `lab2` | лаборант | вносит записи |

## Демо-сценарий (5–7 минут)

1. **`admin` → «Журналы» → «+ Создать журнал»**: создайте журнал из пресета, назначьте
   ответственного и участников (галочки). «Шаблоны форм» — те самые пресеты (T-01…T-12)
   и конструктор. Состав участников существующего журнала меняется кнопкой
   **«Участники и настройки»** на странице журнала.
2. **`lab1` → «Журналы» → Ж-04/01**: «Новая запись» — зарегистрируйте образец.
3. **`lab1` → Ж-04/02**: «Новая запись» — выберите образец, методику, укажите навеску
   и объём: результат считается формулой автоматически.
4. **`lab1` → Ж-04/04 (учёт реактивов) → «Списание»**: списание проходит.
5. **`lab1` → Ж-04/03 (прекурсоры) → «Списание»**: **отказ** — нет отдельного права.
   Выйдите, войдите как `eng1` — списание проходит, событие уходит в журнал и аудит.
6. **`lab1` → любая запись → «Исправить»**: укажите причину (В — ошибка вычисления) —
   и покажите «Историю»: прежнее значение перечёркнуто, видно кто/когда/почему.
7. **`admin` (или `qm`) → «Уведомления» → «Проверить сейчас»**: появятся напоминания —
   истекает стандарт-раствор нитратов, не внесена температура холодильника за сегодня.
8. **`qm` → Ж-04/01 → «Отметить проверку»**; **`head` → журнал → CSV / «Печать»**;
   «Аудит» — полная картина всех действий.

## API (кратко)

Через gateway: `http://localhost:8080/api/...`

| Сервис | Примеры |
|---|---|
| auth | `POST /api/auth/login`, `GET /api/auth/me`, `GET/PATCH /api/auth/users` |
| forms | `GET /api/forms/templates`, `POST /api/forms/templates`, `POST /api/forms/templates/{id}/versions` |
| records | `GET/POST /api/records/journals`, `POST /api/records/journals/{id}/records`, `PATCH /api/records/records/{id}` (исправление с причиной), `POST /api/records/journals/{id}/review` |
| materials | `GET /api/materials/items`, `POST /api/materials/receipts`, `POST /api/materials/writeoffs`, `GET /api/materials/operations` |
| scheduler | `GET /api/notifications/list`, `POST /api/notifications/tick` (админ) |
| audit | `GET /api/audit/events` (QM/заведующий/админ) |

Все сервисы отдают `/health` (внутри сети, без gateway).

## Соответствие ГОСТ ISO/IEC 17025-2019

| Требование / практика СМК | Реализация |
|---|---|
| Исправление: зачеркнуть, указать верное, дату, подпись, причину | `PATCH /records/{id}` — причина обязательна, прежнее значение хранится в ревизии |
| Записи нельзя незаметно изменить или удалить | удаления нет в API; append-only аудит; закрытая запись не правится |
| Периодическая проверка журналов с фиксацией | атрибут «периодичность», отметка «проверено (кем, когда)», напоминание о просрочке |
| Разграничение доступа | роли + членство в журнале + отдельное право на прекурсоры |
| Защита от потери записей | PostgreSQL-том в docker compose; резервная копия — выгрузка тома/БД |
| Сроки хранения и архив | атрибуты журнала; статус «в архиве» = только чтение |
| Идентификация журналов (шифр, форма, ответственный) | реестр журналов (шифры Ж-04/XX) + версии шаблонов |
| Прослеживаемость: образец → методика → данные → результат → материалы | связи записей (ref_journal) и привязка списаний к журналам/записям |

## Разработка без Docker

```bash
# база
docker compose up -d db

# сервисы (каждый в своей папке services/*)
uvicorn app.main:app --port 8001 --reload

# фронтенд (прокси /api на localhost:8080 — поднимите gateway или поменяйте в vite.config.ts)
cd web && npm install && npm run dev
```
